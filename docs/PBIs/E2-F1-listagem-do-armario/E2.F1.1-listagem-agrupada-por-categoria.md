## Contexto

Com a E1.F2.1, o app já cria peças de verdade, mas `WardrobeView` ainda é um placeholder — o cadastro "termina" sem nenhuma prova visível de que funcionou. O armário é a tela principal do produto para a Marina; esta PBI entrega a visão organizada por categoria que `requisitos.md` (Épico 2) pede, e é pré-requisito para as próximas features (filtros, looks).

## Descrição

Implementar `WardrobeView` real: busca `GET /pecas`, exibe agrupado por categoria (título + contagem + grade de miniaturas), trata carregamento/erro/vazio, atualiza ao voltar do cadastro, e passa a viver dentro de uma navegação inferior (Armário/Looks).

**Para na exibição** — tocar numa peça não faz nada, sem filtros, aba Looks continua placeholder.

## Escopo

**Dentro do escopo:**
- `WardrobeView` real: lista agrupada por categoria, em grade, com título e contagem por grupo.
- Ordem fixa (Camisetas, Calças, Vestidos, Sapatos, Acessórios); categoria fora da lista vai para grupo final "Outras".
- Estados de carregamento, erro (com "Tentar novamente") e vazio, e "puxar para atualizar".
- `HomeShell` novo com `BottomNavigationBar` Armário/Looks; FAB "Adicionar peça" só na aba Armário.
- `GET /pecas` ganha `ORDER BY criado_em DESC` (hoje não garante ordem).
- Lista de categorias extraída de `peca_form_view.dart` para um arquivo compartilhado (agora duas telas dependem dela).

**Fora do escopo:**
- Filtros (cor, tecido, estação, ocasião, marca) — Feature 2 do Épico 2.
- Detalhe/edição/exclusão de peça — próxima feature do Épico 1.
- Conteúdo da aba Looks — Épicos 3 e 6.
- Paginação, cache em disco, miniaturas redimensionadas — volume do MVP não justifica.
- Corrigir `imagem_url` absoluta gravada pela E1.F2.1 — ver Riscos; a tela aceita os dois formatos.
- Login real, perfil, aba Preferências — Épico 4.

## Como será feito

- **Estado**: `wardrobe_controller.dart` (novo) com `FutureProvider.autoDispose<List<Peca>>` chamando `pecaServiceProvider.listarPecas()` (importado de `upload_controller.dart show pecaServiceProvider`, mesmo padrão de `peca_form_controller.dart`). `autoDispose` para rebuscar sozinho ao voltar à tela.
- Agrupamento no cliente: função pura `agruparPorCategoria(List<Peca>) → Map<String, List<Peca>>`, testável sem UI.
- **Tela** (`wardrobe_view.dart`, reescrita): `RefreshIndicator` + `CustomScrollView` com `SliverToBoxAdapter` (título) + `SliverGrid` por categoria — slivers em vez de `GridView` aninhado evita `shrinkWrap`. Miniatura via `Image.network(AppConstants.resolveMediaUrl(...))` com `errorBuilder`, mesmo padrão de `upload_view.dart`.
- **Navegação inferior**: `home_shell.dart` (novo) — `Scaffold` + `BottomNavigationBar` + `IndexedStack` (Wardrobe/Looks). `main.dart` passa `home` para `HomeShell`. `peca_form_view.dart` troca `pushAndRemoveUntil(... WardrobeView())` por `HomeShell()`, senão o usuário volta sem a barra inferior.
- **Constantes compartilhadas**: `core/constants/peca_opcoes.dart` (novo) — move `_categorias`/`_ocasioes` de `peca_form_view.dart` para constantes públicas (mudança mecânica).
- **Backend**: `listar_pecas` em `app/api/v1/pecas.py` ganha `.order_by(Peca.criado_em.desc())`.

**Arquivos afetados**: `wardrobe_view.dart` (reescrito), `wardrobe_controller.dart` (novo), `home_shell.dart` (novo), `peca_opcoes.dart` (novo), `main.dart`, `peca_form_view.dart`, `backend/app/api/v1/pecas.py`, `widget_test.dart` (ajustar testes que assumem placeholder).

## Critérios de aceite

- Com peças cadastradas, o armário mostra grupos por categoria (título + quantidade), na ordem fixa.
- Peça com categoria fora da lista aparece em "Outras", não some.
- Sem peças, mostra estado vazio com orientação para cadastrar a primeira.
- Busca em andamento mostra indicador de carregamento.
- Busca falhando (rede, backend fora, 401) mostra mensagem clara + "Tentar novamente", sem travar.
- Peça recém-salva aparece no grupo certo ao voltar do formulário, com a barra inferior visível.
- Alternar Armário ↔ Looks pela barra inferior funciona e mantém a rolagem do armário.
- Dois usuários (tokens com `sub` diferentes) veem só as próprias peças.

## Riscos e pontos de atenção

- `imagem_url` gravada absoluta (`http://localhost:8000/...`) pela E1.F2.1 quebra fora do `localhost` — não corrigido aqui, mas a tela aceita os dois formatos.
- Miniaturas servidas de outra origem (`/uploads`, StaticFiles) — se não aparecerem no Chrome, checar `CORS_ORIGINS`.
- Categoria é `String` livre no banco — "Outras" existe por isso.
- `pecaServiceProvider` mora em `upload_controller.dart`; importar de lá no armário é acoplamento feio, registrado como dívida pequena.
- Estado `processing` (peça em processamento assíncrono) previsto no CLAUDE.md não existe ainda — não tratado aqui.

## Como testar

1. Backend rodando + migrações; gerar token: `cd backend && python scripts/gerar_token_teste.py`.
2. `cd mobile && flutter run -d chrome --web-port=8080 --dart-define=DEV_AUTH_TOKEN=<token>`.
3. Armário vazio → mensagem de armário vazio.
4. Cadastrar 3-4 peças de categorias diferentes (duas na mesma) → cada uma aparece no grupo certo, barra inferior visível.
5. Conferir ordem dos grupos e contagem por título.
6. Inserir peça com categoria fora da lista via `/docs` → aparece em "Outras".
7. Confirmar peça mais recente primeiro dentro do grupo.
8. Gerar segundo token (usuário novo) → armário vazio, sem ver peças do primeiro usuário.
9. Derrubar backend, puxar para atualizar → erro com "Tentar novamente"; subir de novo → lista volta.
10. Rodar sem `DEV_AUTH_TOKEN` ou com token inválido → mensagem de sessão inválida, sem crash.
11. Alternar Armário ↔ Looks, rolar, trocar de aba e voltar → rolagem mantida.
12. `cd mobile && flutter analyze && flutter test`.

## Log de implementação

**Entregue**: exatamente como "Como será feito" — `wardrobe_controller.dart` (novo: `pecaListProvider` + `agruparPorCategoria`); `wardrobe_view.dart` reescrito (`RefreshIndicator`+`CustomScrollView`/slivers para dados, `ListView` com `AlwaysScrollableScrollPhysics` para os estados vazio/erro, para manter "puxar para atualizar" funcionando nesses estados também); `home_shell.dart` (novo, `BottomNavigationBar` Armário/Looks via `IndexedStack`); `peca_opcoes.dart` (novo, `categoriasFixas`/`ocasioesFixas` compartilhadas); `main.dart` e `peca_form_view.dart` atualizados para `HomeShell`; `backend/app/api/v1/pecas.py::listar_pecas` com `.order_by(Peca.criado_em.desc())`.

**Mudanças de escopo**: (1) dois testes pré-existentes em `widget_test.dart` ("App abre exibindo o armário" e o do FAB) passaram a bater numa chamada real de `GET /pecas` depois que `WardrobeView` ganhou busca de dados — isso deixava um timer pendente no ambiente de teste (Dio nunca resolvia a tempo), derrubando os testes. Corrigido sobrepondo `pecaServiceProvider` com um `PecaService` falso (armário vazio) nesses dois testes — não é uma regra nova, só estender o mesmo padrão de fake service já usado em todo o resto da suíte.

**Verificação real**: `dart analyze` limpo (0 problemas). `flutter test`: **15/18 passando** — todos os testes novos (`wardrobe_test.dart`, 8/8: 3 unitários de `agruparPorCategoria` + 5 de widget, incluindo navegação entre abas) e a suíte pré-existente ajustada passam. As **3 falhas remanescentes são as já documentadas no log da E1.F2.1** (`peca_form_test.dart`, problemas de scroll/timing do harness de teste, não da implementação) — pré-existentes a esta PBI, não tocadas aqui. Backend: `python -m py_compile app/api/v1/pecas.py` confirma sintaxe válida; não foi possível ir além (sem venv com as dependências instaladas nesta máquina, mesma limitação já registrada na E1.F1.4).

**Pendente**: todos os critérios de aceite via fluxo real no Chrome + backend local (exige Python/Postgres rodando e interação manual); confirmar via `/docs`/`curl` que `GET /pecas` devolve ordem decrescente de verdade; o teste de "dois usuários veem só as próprias peças" (depende de backend real).

**Decisões não detalhadas antes**: (1) o grid usa `mainAxisExtent: 110` (não o quadrado default do `SliverGridDelegateWithFixedCrossAxisCount`) para manter as miniaturas compactas — sem isso, em telas largas as células ficavam desproporcionalmente altas. (2) "Tentar novamente" do estado de erro usa `ref.invalidate` (sem `await`), consistente com o padrão de retry já usado em `upload_controller.dart`/`peca_form_controller.dart`, em vez de `ref.refresh(...future)` (que o lint do projeto sinalizou como resultado não utilizado).
